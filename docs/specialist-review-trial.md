# Restricted-review development trial

New-model follow-up (2026-10-27): the installed4B candidate completes the same protocol2,
settings/corpus hashes and24 inputs/72 calls. Baseline17/24, self-review20/24 and specialist
20/24; zero wins and zero regressions fail the strict improvement gate. No retries,
retuning, delegation or default changes. Its tool-workflow qualification remains separately
failed; this narrower structured read-only test does not override that result. Evidence:
`.runtime/p2-04-4b-review/validation.json` and `IMPLEMENTATION.md`.

P2-04 A0 is an evaluation prerequisite. It does **not** add a Studio tool, endpoint,
automatic child, task-store relationship or permission grant. Full delegation remains
incomplete until integration and its independent acceptance gates pass.

## Run and scope

With Studio idle and the configured local model available, run:

```powershell
.\.venv\Scripts\python.exe -m local_agent.review_trial --repeats 3
```

The runner uses existing localhost-only model admission, structured output, approved
Coding/Policy reads, source fingerprints, process supervision and evaluation identity
helpers. No model is downloaded, service restarted, command generated by a model run,
or real project submitted. The configured model must support structured output and
the selected thinking setting. There is no cloud fallback or model-specific hardcode.

Eight shipped synthetic Python cases include six defective implementations and two
correct controls, including an instruction-injection comment. Trusted shipped fixtures
and their corrections execute only to establish their declared functional checks.
Workspace files and model responses are never executed as Python.

Each repetition writes one new private case directory containing only `subject.py`
as its model-readable input. All reports anchor findings to that file's existing lines;
out-of-scope paths, duplicate/unknown fields, unsupported tool calls, changed sources,
invalid status or native observations cannot pass the corresponding validation.
Reports remain untrusted observations, never tool or approval authority.

## Comparison and budgets

Each case has a shared first pass, followed by two **alternative** second passes:

- Same-agent self-review retains its first-pass conversation.
- Independent specialist review gets fresh instructions and the prior report as untrusted data.

Both alternatives have the same first pass and one extra model call. The order of their
second passes is counterbalanced across cases/repetitions. Three repeats produce24
paired inputs and72 ordinary model calls, plus at most24 schema compatibility probes.
The baseline is shared, not two independently repeated complete workflows.

Each role gets at most384 output tokens, narrowed from the configured limit, and a
request timeout no larger than30 seconds. A configuration with fewer than three decision
slots or64 output tokens is rejected rather than expanded. A child gets one fixed model
call, one fixed input file, no mutations and no recursive delegation. These are **trial**
budgets, not inherited grants implemented in Studio's task engine.

Owned per-case workers have a100-second parent limit within a600-second elapsed trial
budget, plus startup/cleanup overhead. Ctrl+C uses the existing owned-process cleanup;
the Studio emergency-stop integration for a future review child is still separate work.
The runner refuses while the configured Studio database has an active task. It cannot
reserve the GPU against unrelated clients, so observed timings are not exclusive benchmarks.

## Evidence and interpretation

New UUID directories under `.runtime/review-trials/` retain the manifest, private requests,
reports, source identities, parent/role IDs, native counters and process observations.
Existing runs are never overwritten. Missing/failed observations cannot establish a
measured gate. Fixture provenance cannot establish a live benefit, even if a caller
labels the overall comparison live. Offline caller-supplied records remain unattested.
Exit0 means evaluation coverage completed, not that the specialist passed its benefit
gate. Inspect `location_benefit_observed`; incomplete runs return a nonzero exit.

The independent oracle checks **exact defect locations** against the predeclared fixtures;
it does not certify explanation semantics, arbitrary code or a complete agent workflow.
The candidate must improve over equal-budget self-review without regressing any previously
correct self-review or first-pass case. All24 inputs, three live roles and balanced order
are required. Equal results, regressions and incomplete runs are reported without changing
the oracle or enabling delegation.

Reported p50/p95 cover shared preparation plus the relevant role calls; they exclude
worker startup, final identity checking and supervisor cleanup. Per-case process timings
retain those broader costs. Native token counters are used directly rather than parsed
from model prose. A two-pass role's cost is not a cold-start estimate or proof of GPU use.

Use `python -m unittest tests.test_review_trial -v` for contract regressions. This component
uses Ollama's [structured-output API](https://docs.ollama.com/capabilities/structured-outputs).
Actual results, source hashes and remaining integration work belong in IMPLEMENTATION.md.

## Observed candidate result (2026-10-25)

The first protocol completed24 inputs/72 ordinary model calls but obtained only6/24
exact-location matches for both first pass and specialist, versus9/24 for self-review.
It omitted schema-in-prompt grounding and presented source as an escaped string.
That complete negative run, source archive and wheel are retained as protocol1.

Protocol2 includes the same JSON schema in the protected instructions and displays
numbered source lines. The eight fixtures and oracle digest are unchanged. All24 inputs/
72 ordinary model calls completed on qwen3.5:9b/Ollama0.40.7, with balanced12/12 order.
First pass matched18/24, self-review21/24 and specialist19/24. The specialist had zero
wins over self-review and two regressions, failing the predeclared benefit gate.
No cases or failed repetitions were removed or replaced. These are exploratory protocol
revisions on the same fixtures, not held-out evidence for broad prompt improvements.

Observed workflow p50/p95 seconds: first pass8.231/9.377, self-review9.260/10.664,
specialist9.352/11.259. The specialist's mean second-pass overhead versus self-review
was+0.090s. Model identity fields retain the existing evaluator's legacy weights_sha256
name for an Ollama manifest digest, not tensor-file attestation. Native rate is generation
only and excludes model loading, prompt evaluation, process startup and cleanup.

**Decision:** retain this development evaluator and its negative evidence, and leave
Studio delegation inactive. A0 can close as an evaluated prerequisite; full P2-04 is
incomplete and requires a demonstrated benefit before integrated child machinery is retained.
Protocol1 run: `106d06fdea764917acf27263d3658269`;
protocol2 run: `d805628ae96c4dc3ab6dd4cd4f62851a` under `.runtime/review-trials/`.

A final defensive guard binds the initial source snapshot across the compatibility
